**每一节要写什么。** 这是给要动手写报告的人看的：条目页是一张格子表，缺哪一格就补哪一格。

| 条目 | 必填项 |
|---|---|
| 行业条目 | 定义与边界 · 规模 · 增速 · 集中度（CR4 / HHI）· 价格带分布 · 季节性 · 谁量的、什么口径、哪一版 |
| 竞品条目 | 名称与法律主体 · 所属品类 · 规模与份额 · 增速 · 价格带 · 投放强度（公开信号）· 声量与情绪 · 每一项的来源与日期 |
| 品牌条目 | 主体与品牌的关系 · 所属品类 · 份额 · 价格溢价 · 搜索与声量信号 · 公开财务信号 · 口径与日期 |
| 品类条目 | 品类边界（怎么算进来、怎么算出去）· 规模 · 价格带分布 · 促销节奏 · 季节性 · 渠道结构 |
| 用户条目 | 人群定义 · 规模 · 需求强度排序（别用平均数）· 决策链 · 抽样方式与样本量 · 三种数据源的偏差方向 |

每一格都写五件事：**是什么 / 分母是谁 / 谁量的 / 什么时候会骗你 / 怎么复现。** 这一套叫「口径卡」，是全站最该统一的东西。

**三种写法。**

**方法论页** —— 场景（能闻到）→ 口径卡 → 图（2–4 张数据图）→ 真案例 → 你自己怎么算（三步以内）→ 结论 → 下一节 → 数据 / 复现。

**条目页** —— 这是什么、它在市场里的位置 → 必填项逐项填 → 图 → 读的时候注意什么 → 口径与来源。

**字典页** —— 定义 + 公式 + 图（标 illustrative）→ 什么时候会失效 → 在哪篇用过。

结构图只画报告里真有的东西：报告目录、价值链、投放漏斗、决策流程。不画概念图。

**每页的头三行是规矩。** 读者第一眼看到的就是这三样：

1. **一段场景** —— 能闻到的，不是定义的
2. **一张能看懂的图** —— 先看懂，再能换数
3. **一句能带走的话** —— 念给同事听也成立

表格、必填项、口径卡，一律不放在第一屏。

**参与改进的三条口子。**

- **改一个格子** —— 条目页缺哪一项就提 PR 补上，站内引用它的页面一起受益
- **换一组数重画** —— 格子里的图 URL 可以换数，用自己的数重画一遍发过来
- **加一条公开序列** —— 数据源台账是一份清单，多一个人加一条，全站就多一个能查的数

改一格 = 改整份报告。这是这个站跟「一堆文章」的根本区别。

**AI 干哪一段活。**

```
问题 → 取数 → 填格子 → 算 → 出图 → 写解读 → 挂引用 → 交稿
      ↑公开序列/交接表  ↑口径卡    ↑脚本  ↑draw URL
```

人做：定问题、判定口径对不对、判断结论能不能拿出去讲、签字。AI 做：取数、算、出图、起草、写解读、挂引用。

边界：**AI 能替你算出 316%，不能替你判断这个数该不该拿给老板。口径这一步必须人确认。** draw 是铰链——每个数点一条 URL，打开见全部参数，改数就能重画，发出去还带着「这是用 x-cmd draw 出的」。
