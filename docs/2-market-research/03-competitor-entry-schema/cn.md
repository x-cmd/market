# 对手的资料，要经得起别人查

竞品表里有一栏是空的，别的栏都填了。你在会上一眼扫过去，看到空的那栏就跳过去了。

半年后有人问你：这家到底多大？

你把表翻出来，那一栏还是空的。旁边几栏的数字都很干净，看不出它们是哪天、哪个口径。

问题不是这栏空着，是整张表看不出哪一格能信。名字有了，份额那格是空的——这张表做了一半，做的那一半还没标日期，等于没做。

一份能被别人核对、被别人更新的竞品资料，靠三样东西：数字出自哪、截至哪天、怎么算出来的。

## 表做了一半，为什么没人能用

**不是格子少，是格子之间没有共同的约定。**

## 这一页要填哪些格子

这一页用四家网站分析工具做一份完整的样例：umami、Matomo、PostHog、Plausible。四家都开源、都卖托管版、都能查到 GitHub 上的公开数据，正好能把这八格里最难填的几格暴露出来。

| 格子 | umami | Matomo | PostHog | Plausible |
|---|---|---|---|---|
| 主体 | umami-software | Matomo（法国） | PostHog Inc. | Plausible（11 人） |
| 品类 | 自托管网站分析 | 自托管 + 托管 | 产品 + 网站分析 | 隐私优先分析 |
| 规模 | 未披露 | 未披露 | 未披露 | 未披露 |
| 增速代理 | 1406 次提交 | 1065 次 | 41943 次 | 610 次 |
| 价格带 | $0/$20/$200 月 | 云 €29，自托管 €230 起 | 公开页读不出 | $9/$14/$19 月 |
| 投放强度 | 无公开信号 | 无公开信号 | 无公开信号 | 无公开信号 |
| 声量与情绪 | 未做 | 未做 | 未做 | 未做 |
| 来源与日期 | GitHub API + 官网报价 | 同左 | 同左 | 同左 |

这张表里有三件事值得停下来看。

第一，「规模」四家全是空的。这四家都不公开营收，公开渠道查不到就是查不到。

第二，「增速」这格填的不是营收增速，是过去 12 个月的提交数。它衡量开发活跃度，不是生意增长。口径不写出来，它会被当成营收增速用。

第三，PostHog 的价格格是空的，另外三家都填上了。它的报价页是浏览器端渲染的，静态抓取只能拿到骨架。这恰好证明了这张表该有的样子：一个空格比一个猜出来的数有用。

## 每一格都要说清是哪来的

**数字本身不说明任何事，出处才说明。**

份额要有分母。价格带要写取哪天、哪些渠道、哪种产品形态。投放强度要标明是公开信号还是估算。

看 Matomo 那一行：云版 €29，自托管 €230 起。同样一个「Matomo」，两个价格带差了快八倍——托管版是别人替你跑，价是服务费，自托管版是软件许可，价是买断加维护。只写「Matomo €29」的人，卖的和买的人想的不是一件事。

### 三个格子最容易含糊

**规模**这一格，说的是对手有多大。营收是首选，拿不到营收可以用公开的交易额、门店数、员工数。关键是写清测的是哪一段、什么时候。

**投放强度**这一格，指对手在广告上花了多少力气。公开信号有几种：广告库里的投放素材数、招标公告里的投放计划、财报里的销售费用。估算的做法是拿行业平均获客成本倒推。这里四个格子全是空的，因为这四家都做开发者工具、自助付费为主，公开渠道查不到它们的广告投放数据。写「未做」比写行业平均值有用，后者会被当成这家的数据用。

**声量与情绪**这一格，指外面怎么议论它。搜索热度、社交提及数、评论里的正负比例。免费工具有个特殊之处：GitHub 的 issue 数和 fork 数本身就是一种声量，只是它只覆盖愿意在公开仓库里说话的那部分用户。

这个数能填，但填的时候要写清三件事：从哪天到哪天（2025-11-01 到 2026-11-01）、算什么（主仓库的提交记录）、它不代表什么（不代表营收，也不代表用户数）。它是「开发活跃度」这格的一个代理值。代理值没错，错的是把它当成增速本身。

## 每一格都要标上截至哪天

**日期不是装饰，是这格数字的一部分。**

Star 数是快照。今天 39990，明天可能就 39993。它既是这个数的一部分，也是这个数过期的证据。

过期的格子不要删。删掉以后，没人分得清「查过了，确实没有」和「还没查」。前者不用再查，后者要排进日程。

这一页的取数日期是 2026-11-08（GitHub API 快照）与 2026-11-09（官网报价页）。价格尤其需要日期，报价会变。下面这张图把三家能查到价格的排在一起。

最低一档到最高一档差了二十五倍。这个跨度里藏着产品形态、地区、计费量三种限定条件。少写一个，这张图就会被人读成「Plausible 比 Matomo 便宜七倍」。

### 主体这一格也有坑

「umami」是一个 GitHub 仓库名，不是一家公司名。仓库背后是 umami-software 这个组织，主体是个人开发者。PostHog 是 PostHog Inc.，Plausible 是一家 11 人的自筹团队，Matomo 是一家法国公司，还分 Matomo 和 InnoCraft 两条线。

这一格看着最简单，填错的后果却最大：主体填错，后面每一格的钱和数都可能挂在一个错的公司上。

## 查不到就空着，别填一个推算值

**一个假的精确数字，比一个诚实的空格危险得多。**

空格能告诉下一个读表的人：这里没查，或者查了没有。推算值不能。

「规模」四家全空。为什么不去查一份行业报告里的市场份额，或者按用户数乘一个 ARPU？因为那些数有出处，但不是这四家的出处。你把它填进去，读表的人不会去追那家报告的假设，他只会看到「Matomo 市场份额 3.2%」，然后拿去跟别的数比。

PostHog 的价格格空着也是同一个道理。它的报价页是浏览器端渲染的，静态抓取拿到的 HTML 里没有价格数字。可以用别的方式确认，但只要确认的方式没写下来，这个格就不该填。写「公开渠道查不到（报价页为客户端渲染，2026-11-09 抓取）」，比写一个数有用。

留空不是缺陷，是信息。哪些格子留空，说明这些方向你还没掌握，也说明这张表在哪一步能被人接着往下做。

## 别人查得动、也改得动，靠的就是来源、算法和日期

**一份能被别人查、别人改的竞品资料，靠的是来源、口径、时间三样东西。**

| 值 | 来源 | 口径 | 截至 |
|---|---|---|---|
| umami 提交 1406 | GitHub commits API | 主仓库提交记录 | 2026-11-08 |
| umami Pro $20/月 | umami.is/pricing | 月付，含 100 万事件/月 | 2026-11-09 |
| Matomo Cloud €29/月 | matomo.com/pricing | 月付，5 万 hits/月 | 2026-11-09 |

| Plausible Starter $9/月 | plausible.io | 月付，1 万 PV/月 | 2026-11-09 |

| 规模、投放强度 | — | 未公开，无来源 | — |

来源、口径、截至这三列是这份表真正的内容。数值那一列删掉，整张表还能用，这三列删掉，整张表就废了。

GitHub 那一格尤其能说明问题。star 39990、fork 8504、open issue 150、许可 MIT、最后推送 2026-11-07——五个数全部来自同一个接口调用，任意一个人跑同一条命令都能拿到一样的结果。这就是「查得动」的意思。

下次更新要改的只有两个地方：值和截至日期。来源和口径不变。改完以后，别人能拿新旧两个快照对比，看出这家变了没有。

一份对手资料真正的价值，不在你读它的那一天，而在三个月后你还敢不敢照着它去核。
