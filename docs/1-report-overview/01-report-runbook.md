# 一份市场报告怎么跑出来

八步。每一步写清四件事：**这一步干什么、谁做、产出什么、怎么验。**

这套流程是给「人 + AI agent」一起用的。分工只有一句话：**有明确输入输出的活给 agent，要人拍板的事留给人。**

agent 能替你把 4100% 和 −63% 都算出来，也能把图画好、把段落写顺。但它替你做不了三个决定：这次要回答什么、这个数按哪个口径算、这个结论能不能拿出去讲。这三个决定做错了，后面做得越漂亮，错得越远。

## 第 1 步 · 把问题说清楚

**这一步行业里叫 brief（需求简报）。** 一张纸，四行。

- **谁做**：人。agent 可以帮你把模糊的描述拆成候选问题，但选哪个是人。
- **输入**：你现在脑子里的那个模糊问题。
- **产出**：一句话的问题 + 一个交付物 + 给谁看 + 什么时候要。
- **怎么验**：这句话能不能被回答？答不上来的问题，写成报告就是浪费时间。

模板长这样，四个空填满：

```
我们要回答 ________；
交出的是 ________（一页 PPT？一份带图的文档？一张表？）；
给 ________ 看；
________ 之前要。
```

> 交付物写不清楚，后面每一步都会返工。**「一份市场报告」不是交付物，「一页说清楚我们该不该进这个品类」才是。**

## 第 2 步 · 框范围：这次算的是哪块地方

**这一步行业里叫 scope（框范围）。** 把「市场」这个词落到实处——哪块地、哪个时间窗、算不算自己。

- **谁做**：人定边界，agent 查边界能查到的数。
- **输入**：第 1 步的问题。
- **产出**：一行范围定义 + 一份实体清单（算哪些公司、哪些品类、哪些地区）。
- **怎么验**：拿这行定义去查，能查到数；换一行定义，查到的数明显不同——那就说明范围这一行值得再想。

范围里最容易漏的三样：

- **要不要含自己** —— 份额的分母里含不含你，差很多
- **按什么分类** —— 用 NACE 行业码，还是用你自己的品类
- **到哪一年为止** —— 数据有滞后，拿去年的数讲今年的事很常见

## 第 3 步 · 定一个「就是这个数」

**这一步行业里叫 source of truth（唯一数据源）。** 一个指标只能有一个权威出处，别处引的数都得能追回它。

- **谁做**：agent 找，人拍板。
- **输入**：范围 + 要算的指标。
- **产出**：每个指标一张**口径卡**（metric card）——见 `spec/metric-cards.yml`，那是给 agent 直接吃的机器可读版本。
- **怎么验**：拿卡片里的命令跑一遍，能跑出卡片上写的那个数。对不上，卡片就是错的。

> 口径卡里最容易漏的是 **caveats（注意事项）**：这个数覆盖了谁、没覆盖谁、哪一年之后不能跟以前比。写下来，以后每次复用都省事。

## 第 4 步 · 算

**这一步行业里叫 compute（计算）。** 照口径卡上的公式算，别自己发明。

- **谁做**：agent。
- **输入**：口径卡 + 原始序列。
- **产出**：算好的数 + 算的时候用的参数。
- **怎么验**：拿一组手算能验的小样本对一遍；能出区间的要出区间，别只给一个点。

这一步最容易出的错不是算错，是**算的是另一个东西**：把占比算成分母不同、把名义当实际、把季调当原始。口径卡上写了什么，就算什么。

## 第 5 步 · 画

**这一步行业里叫 visualize（出图）。** 每节配一张图，一张图只讲一件事。

- **谁做**：agent。
- **输入**：算好的数 + 这节要说明的那件事。
- **产出**：一条 draw URL——**数据装在链接里**，人点开能看全部参数，agent 能改数重画。
- **怎么验**：把 URL 打开，图和正文说的对得上；把数换掉，图自己会变。

> 三种图各管一段：`/draw/echarts` 画数据图，`/draw/mindmap` 画结构，`/draw/archmap` 画架构。
> **结构图只画业务里真有的东西**（报告目录、价值链、投放漏斗），不画作者自己的思维图。

## 第 6 步 · 写

**这一步行业里叫 narrative（叙事）。** 每节一段人话 + 一句能带走的判断。

- **谁做**：agent 起草，人改。
- **输入**：这节的图、口径卡、结论。
- **产出**：每节一段，加一个 takeaway（这句是读者唯一会记住的）。
- **怎么验**：念给同事听，听的人能不能复述。复述不了就重写。

> 写正文有三条硬规矩：开头给场景不给定义；黑话出现当场翻译；**不教人怎么做生意**——只讲这个数怎么算、怎么读、这个口径是什么。

## 第 7 步 · 验

**这一步行业里叫 QA（验收）。** 十条，交稿前逐条过。

1. 每个数都写清了是谁量的吗？
2. 每个占比都写清了分母是谁吗？
3. 每个数都标了截至哪天吗？
4. 覆盖了谁、漏了谁，写了吗？
5. 名义还是实际，分清了吗？
6. 要出区间的，出了吗？
7. 图注写了口径吗？
8. 哪些数是估的，标出来了吗？
9. 结论能拿去开会吗？
10. 数据能重跑一遍吗？

- **谁做**：agent 先自查一遍，人过第二遍。
- **怎么验**：两条都过才算完。第 10 条最容易被跳过，也最不能跳。

## 第 8 步 · 交

**这一步行业里叫 deliver（交付）。** 三样东西一起交，少一样这份报告就不可信。

- **产出**：报告本身 + 数据附录（每个数的来源、命令、截至日期）+ 复现脚本（`spec/` 里的口径卡和取数命令）。
- **怎么验**：把脚本交给一个没参与过的人，他能跑出同一批数。跑不出来，交出去的就是纸上谈兵。

## 照着跑一遍：产出长什么样

下面是一次真实跑通的片段，用的是「欧盟电商渗透率」这个题。数据是 Eurostat 企业 ICT 调查（`isoc_ec_evaln2`），取自 2025 年 11 月。

**第 1 步 · Brief**

```
我们要回答：欧盟的「电商占比」到底是多少、别人引用的是哪个口径；
交出的是：一张能直接放进报告的占比图 + 一段能念给老板的解释；
给：市场部老大；
本周五之前要。
```

**第 2 步 · Scope**

范围：欧盟 27 国；行业 NACE C-E（批发零售、住宿餐饮、交通）；雇员 10 人及以上；年份 2009–2025。**不含自己**（这是一个行业总量，不是一家公司）。

**第 3 步 · Source of truth**

```yaml
id: ecom_share_of_turnover
label: 网络销售占企业总营业额
value: 19.82          # 2024，欧盟整体
unit: "%"
denominator: 企业总营业额（雇员 10 人及以上，NACE C-E）
source:
  provider: Eurostat
  dataset: isoc_ec_evaln2
  series: A.GE10.C-E.E_AWSVAL.PC_ETURN.EU27_2020
  command: x dbnomics data Eurostat/isoc_ec_evaln2/A.GE10.C-E.E_AWSVAL.PC_ETURN.EU27_2020
caveats:
  - 只覆盖雇员 10 人及以上的企业，小店和个体户不在里面
  - 只覆盖 NACE C-E 行业
  - 2025 的调查覆盖范围有变，跟 2024 不能直接比
```

**第 5 步 · 画**


数据装在链接里：打开看得到全部参数，把数换成自己的，图自己重画。这张图是十个国家各两根柱子，左边是全部网络销售，右边是只算卖给消费者的——希腊 81% 对 42%，匈牙利 31% 对 0.9%。

**第 6 步 · 写（这一节的 takeaway）**

> 同一个「电商占比」，欧盟整体 2024 年是 19.82%；只算卖给消费者的那部分是 8.49%。差的那一倍不是谁算错了，是分子里装了 B2B。匈牙利更极端——营业额的 30.85% 来自网络销售，但其中只有 0.92% 是卖给消费者的，其余几乎全是批发商卖给零售商。**所以「某国电商占比 31%」这句话，不等于「这个国家三成的人在网购」。**

**第 7 步 · QA**

十条过了八条。第 4 条（覆盖了谁、漏了谁）这里要写明：雇员 10 人以下的企业不在调查里。第 9 条过了——这段话能直接念给老板。

**第 8 步 · 交**

报告 + 数据附录 + 一条复现命令（上面那句 `x dbnomics data …`）。

## 每周能重跑的那一份

**固定形状，数字每周换。** 这是给执行岗每周交的那份数，也是给咨询方复用的一套模板。

| 交什么 | 长什么样 | 谁做 |
|---|---|---|
| 3 张图 | 份额图、趋势图、价格带图 | agent |
| 1 张表 | 本周的关键数 + 对上周的变化 | agent |
| 5 句话 | 五个 takeaway，一句一个数 | agent 起草，人改 |
| 1 条命令 | 下周怎么重跑 | agent |

三张图的数据从哪来、口径是什么，在各自的页里写着。**每周跑一次的必须是同一批图**——形状固定，读者才会盯着看变化。

## 交给 agent 的时候，给它三样东西

1. **这一步要干什么**（一句话，别让它猜）
2. **口径卡**（`spec/metric-cards.yml` 里那张，别让它自己找数）
3. **做完怎么验**（一句话，能自动查最好）

例：

```
按 spec/metric-cards.yml 里 ecom_share_of_turnover 这张卡取数，
算出 2024 年欧盟整体的网络销售占营业额比重，
和只算 B2C 的那个数并排画成一张双柱图，
用 /draw/echarts，w=760 h=420，alt 用 eu2024_two_numerators。
画完把图里两个数念给我听，对不上卡上的值就别交。
```

最后一句是重点：**给 agent 的活一定要带上验收标准**，否则你拿到的是一份看起来很像的交付物。

## 这个站的分工

- **散文给人看**：每页讲清一个数怎么算、怎么读、什么时候会骗你
- **`spec/metric-cards.yml` 给 agent 吃**：机器可读，不用读懂中文
- **`/draw` 的 URL 是中间格式**：数在链接里，人能改，agent 能重画

**人做四件事**：定问题、框范围、判口径、签字。其余的交给 agent。
